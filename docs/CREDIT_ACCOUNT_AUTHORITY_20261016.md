## Authority audit scope and compatibility

The current-response boundary validates transaction and account replacement
statuses, supplied issuer/role metadata, exact profile/account routing keys,
duplicate identities, month identity/coverage and monetary/installment evidence.
Owner labels belong here because `creditProfilesShareDiscoveredIdentity` uses
them to reconcile profiles; cosmetic `label`, descriptions and card display
names remain presentation data.

Omitted account statuses retain the established older-response inference.
Omitted issuer/default-account metadata preserves an existing exact-ID profile.
Actual network account rows require a nonempty string key; partial producer
month models share the validator before they acquire an account identity.
Persisted historical feeds continue through `normalizeCreditSync` without the
network decoder. No provider credential format, historical transaction ID format,
ACK implementation or settled persistence architecture was redesigned.
Historical vault entries for unsupported issuers are filtered before strict
current-profile projection; supported current identities still cross the guard.

All eleven mutations remove a real production check, assert that unmodified code
rejects the input, execute the mutated producer/decoder and observe the resulting
authority in the actual merge implementations. Historical algorithm/hash baselines
remain immutable, with narrowly scoped projections for the separately tested
status and omitted-metadata changes. Startup source/module budgets are unchanged;
no additional lazy loading was introduced.
