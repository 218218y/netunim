# Local Finance connection import ownership

Nine actual pre-change cases demonstrated that a selected import could target a
replacement paired device after status, file reading or confirmation; late
replacement/publication could announce the former device's result or expose its
private error; two imports could overlap; a nonnumeric Bridge version bypassed
the v66 gate; and a native picker click failure leaked its appended input.

Both applications now use one canonical private import runtime with six required
ports: pairing, local transport, owned file selection, document preparation,
presentation and protocol. It accepts work before status and captures device
authority across every asynchronous boundary, including publication. A single
flow owns the selection and confirmation. Import requires explicit `true` from
the existing confirmation dialog; cancellation and superseded work remain quiet.
Unknown version evidence cannot grant permission. The minimum supported import
version stays 66; Bank financial synchronization separately requires v74.

The native file owner controls the hidden input and listeners, the open selection
and already accepted `File.text()` work. Failure/cancel/disposal remove the input
and listeners. Disposal resolves an open selection, while drain retains an
accepted file read. Strict contracts cover both real implementation bodies,
negative consumer shapes and mutations that replace a boolean result or
asynchronous drain with fabricated evidence.

Kupa Bank and Orders Finance join the importer in pending/drain/dispose. Import
publication receives its captured synchronous guard and rechecks it before and
after the Bank/Credit status reads, before rendering. Construction remains inert,
and the importer is bound only after the shell modal port exists. The broad
callable `createFinanceConnectionImporter` and unowned
`chooseFinanceConnectionImportFile` exports are retired; no production
compatibility alias remains.

The reviewed document parser, size limit, replace format, portable
`connectionKey`, unambiguous historical `profileId` fallback and summaries are
protected by an immutable pre-change AST fixture. Required adapters preserve
password whitespace and current wire payloads. The Bridge's atomic DPAPI vault,
provider/retry/fallback behavior, storage formats and deployed SQL are unchanged.
Historical input formats remain active readers, not parallel write paths.

Focused models cover device changes, serialization, selection cleanup, all
disposal phases, cancellation and success/cleanup warning outcomes. Twenty
registered native browser cases run the actual Kupa/Orders actions with native
files/confirmation and loopback responses. They prove accepted-work drain,
input removal, suppression of foreign publication, exact Main/Shared IDB records,
unchanged business state and note recovery after reload.

This slice does not finish Finance provider/lease orchestration or validate every
business/RPC envelope. A local import is neither a cloud write nor a financial
durability receipt.
