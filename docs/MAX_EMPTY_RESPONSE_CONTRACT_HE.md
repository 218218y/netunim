# חודש ריק מאומת ב־MAX — Bridge 88

## מקור ההכרעה

לאחר Bridge 87 אומת בחשבון חי: אוקטובר–דצמבר 2026 מחזירים JSON עם
result ורשימת תנועות, בעוד ינואר–נובמבר 2027 מחזירים HTTP 200, JSON
ומעטפת עם `returnCode`, `rcDesc`, `result:null`, `correlationID`.
אבחון 4 חשף את המבנה, אך לא שמר את ערך הקוד העסקי.

נבדק קוד התצוגה הציבורי של הספק עצמו, מתוך route של transaction-details:
[474-es2015.8ff18601db0798ac9733.js](https://www.max.co.il/474-es2015.8ff18601db0798ac9733.js).
הקודים 10 ו־11 מוצגים כ־“לא קיימות עסקאות בטווח התאריכים שבחרת”.
קוד 9 הוא אי־יכולת זמנית להציג עסקאות; קוד 13 הוא חריגה ממגבלת התנועות.
האתר מעבד result עם תנועות רק בקוד הצלחה 0.

## החוזה המיושם

- רק קוד מספרי 10/11, result מפורש שהוא null ומעטפת בעלת ארבעת
  השדות המאומתים בדיוק מאשרים תשובת no-transactions. טיפוסי rcDesc
  ו־correlationID מוגבלים; שדות נוספים או result עם מידע גורמים לדחייה.
- קריאת החודשים נשארת בהיקף כל המשתמשים והכרטיסים (`-1`), ללא החלפת
  טווח החודש או סינון כרטיסים חדש. היעדר כרטיסים מזוהים עדיין אינו הצלחה.
- תשובת result:null לבדה, קוד 0 עם result חסר, קוד מחרוזת, מעטפת חסרה,
  שגיאת HTTP או JSON פגום אינם מאשרים חודש ריק.
- קוד 9 מסומן כזמינות ספק זמנית; 13 מציין שפירוט התנועות לא התקבל במלואו.
  בשניהם אין fetchedAt חדש או אפס מאומת. בתחזית הם כשל כיסוי שמבודד
  מהליבה; בליבה הם מפסיקים פרסום. קוד דחייה עסקי לא מוכר מפסיק את הפרופיל.
- הודעת הספק על חודש ריק אינה עוקפת את הגנת ההיסטוריה: תנועות מוגנות
  שכבר נשמרו נשארות, ומחיקה סותרת נחסמת גם במצב recovery ובשני האתרים.

## אבחון ואימות

Bridge 88, סכמת MAX v7 ואבחון 5 מוסיפים את returnCode כמספר עסקי מוגבל,
את טיפוסו, את טיפוס rcDesc ואת דגל סינון הכרטיסים אם הוחזר. ערך rcDesc,
מזהה הקורלציה של הספק וגוף HTTP אינם נשמרים בראיה המבנית החדשה.
האבחון מבחין בין verified_empty, provider_unavailable, provider_limit
ובין תשובה לא מזוהה. אין המצאה של אופק זמינות קבוע של MAX.

בדיקות הקבלה מכסות קוד ריק אמיתי, קודים 9/13, קוד לא מוכר, מעטפת סותרת,
היקף כרטיסים, פרטיות, שימור תנועות והגנות שחזור. לאחר הפריסה נדרשת ריצה
חיה שמאמתת איזה returnCode התקבל בפועל בחודשי 2027. אין לקבוע מראש
שכל result:null הוא בהכרח קוד 10/11.
