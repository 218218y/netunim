# Owner transfer evidence

The transfer coordinator is now a strict checkJs root. Owner-binding, detached
bootstrap and verification replies enter as unknown and are decoded before
source capture, remote effects, owner activation or visible model installation.

Reproduced gaps were a missing comparison against the saved target proof after
restart and unrestricted spreading of a verification reply into view identity.
Malformed phases/identities/proofs and substituted transition replies now stop
while the durable handoff remains locked. Target states/revisions must match
the frozen proof in both recovered and active phases. Only validated view fields
are projected; reply metadata cannot replace the app, account, intent or ID.
Canonical SHA-256 hashing retains its public bootstrap export and Shared Checks
projection. Semantic JSON comparison tolerates object-key ordering. No eager
module or startup budget was added.

Evidence includes source/target crash-resume cases, both recovered and active
proof changes, malformed state/revision/identity matrices, transition substitution,
negative checked consumers, and an actual implementation mutation reproducing
unsafe completion when the frozen-proof comparison is removed. Existing native
IDB owner transfer and two-computer gates remain part of full branch verification.

This does not claim whole IndexedDB/runtime or owner-binding implementation
typing, or live provider / physical-machine validation.
