# השלמת אבטחה — 9 בנובמבר 2026

זהו דוח קוד ותכנית שחרור. בדיקות CI אינן בדיקת חדירה או הוכחה לביצועים
בשלושת מחשבי העבודה. אין כאן אישור ש־MFA, BitLocker או התקנה מקומית כבר בוצעו.

## שינויים ותוצאות שניתן לשחזר

1. מדידת חיפוש מקצה לקצה בשעון מונוטוני, כולל פרסום ולוג. השדות החדשים
   מפרידים Everything, אימות מועמדים, שורשים, נתיבים, הסתרה, PDF ופרסום.
   כותרת Server-Timing מתארת גם בקשות תצוגה, Office ותוכן בינארי. גבולות המדידה
   מפורטים ב־DOCUMENT_BRIDGE_MEASUREMENT_20261109.md.
2. פרטיות לוגים: אין שמירת שאילתה, נתיב, תוכן, תגובה מקורית או הודעת חריגה.
   לוג של 1MiB ועד שלושה גיבויים, מחיקה לאחר שבעה ימים, ניקוי אוטומטי של
   הלוג הישן בהפעלה ראשונה. המפתחות, ההגדרות והאינדקס נשמרים. פרטים ומגבלות
   ב־DOCUMENT_BRIDGE_LOG_PRIVACY_20261109.md.
3. תיקון נוסף שהוכח בקוד: מנגנון האימות החוזר לפני פרסום תוצאות היה קיים
   בבעל החיפוש, אך לא הועבר אליו מהמחבר בפועל. החיבור תוקן. בדיקה מחליפה
   הרשאה בין קריאת המועמדים לפרסום ומוכיחה שלא נוצר מזהה לקובץ שנחסם.
   סינון חדש בשלב הזה מסומן partial; הסרת שורש גורמת לכישלון ללא פרסום.
4. CI ב־Windows מפעיל במפורש בדיקות כונן ממופה, הרשאה חוזרת, מדידות ופרטיות.
   נוסף כלי מדידה שאינו שומר מחרוזות חיפוש, נתיבים או תוכן בדוח.

בדיקות השוואה שומרות את דוגמאות המקור ללא שינוי: 4,608 שילובי חיפוש,
108 שילובי recent, 864 תצוגות PDF ו־720 תרחישי תחזוקה. הבדלי זמן ולוג מכוונים
נבדקים בנפרד; בדיקות התוכן, הסדר, ההרשאות, היומן והסנכרון נשמרו.

## ביצועים: מה נמדד ומה עדיין חסר

הבסיס 150–190ms לחיפוש שם וכ־500ms לתוכן נמסר בסקירה שהתקבלה; הוא לא נמדד
מחדש בשלושת המחשבים. אין להשוות את elapsedMs הישן לחדש כהוכחת האטה: הישן
החסיר עבודה. הבדיקות הסינתטיות מוודאות שעיכוב של 45ms באימות ו־25ms בלוג
נכללים בזמן הכולל. אלו בדיקות נכונות מדידה, לא זמני Everything אמיתיים.

לא נוסף מטמון הרשאות ולא שונה מנוע החיפוש. האימות האחרון שהוחזר למסלול
מוסיף עבודה אמיתית ומדידה ל־publicationMs; נדרש Baseline במחשב הראשון לפני
עדכון שני האחרים. אין לטעון שאין רגרסיה ב־P95 לפני המדידה המקומית הזאת.

## סדר פעולות ידני

1. להמתין לסיום שמירות/העלאות בכל מחשב ולבדוק שאין שינוי מקומי שלא נשמר.
   למשוך main נקי, ולהתקין מחדש Document Bridge 48 במחשב הראשון דרך
   `netunim-orders\document-bridge\install_document_bridge.bat`. Bank Bridge 78
   נשאר הגרסה הקודמת בשלב זה; אם שוחרר עדכון תלויות נפרד, לפעול לפי דוחו.
   git pull לבדו אינו מחליף runtime מותקן. לפרוס את האתרים המעודכנים דרך
   תהליך הפריסה הרגיל; הלקוח דורש התאמת גרסה.
2. לוודא Allowlist בשני המחברים ורק Origins שנבחרו במפורש. לבדוק שהתיקיות
   המורשות מצומצמות; כונן שלם מצריך צורך עסקי ואישור מקומי. לא למחוק פרופילים,
   נתוני דפדפן, מפתחות, אינדקס או נתונים שלא הסתנכרנו.
3. לבדוק חיפוש, PDF רגיל ואינטראקטיבי, Word/Excel, תצוגה חוזרת וסנכרון
   בנק/אשראי רגיל. למדוד את המטריצה להלן; לבדוק הרשאות אחרי הסתרת קובץ או
   הסרת תיקייה, גם עם תוצאת חיפוש שכבר הופיעה. רק אחרי קבלה לעדכן מחשבים 2–3.
4. להשלים MFA בזמן שתבחר: לפתוח security.html באתר ההזמנות או הקופה, להיכנס,
   לרשום מאמת אישי ולאמת קוד; לבדוק התחברות חוזרת בכל המחשבים. לשמור אמצעי
   התאוששות מוצפן מחוץ למחשבים. אין לשתף seed/קוד/מפתח עם תמיכה.
5. להשלים BitLocker ובדיקת Defender, נעילה אוטומטית, הרשאות משתמש ותיקיות,
   גיבויים מוצפנים ושחזור. לגבות בנפרד ובאופן מוצפן את מפתחות Google OAuth;
   עותק DPAPI במחשב יחיד אינו גיבוי בלתי תלוי. לבדוק שחזור בלי לחשוף מפתח.
6. לפני שליחת אבחון ישן, לבדוק בנפרד INSTALLATION-LOG, bridge-console.log,
   קובצי מתקין ואבחונים שכבר יוצאו. ניקוי הלוג החדש אינו מוחק עותקים ישנים
   במקומות אחרים.

## מדידות מקומיות מסודרות

ליצור מקומית בתיקיית .work קובץ plan.json, עם כינויים בלבד למחשב ולתרחישים:

```json
{
  "machine": "computer-1",
  "origin": "https://orders.bargig-furniture.com",
  "repetitions": 20,
  "warmups": 3,
  "scenarios": [
    {"id":"case-01","operation":"search","search":{"query":"בדיקה","scopePath":"C:\\Business","mode":"everything","limit":150}},
    {"id":"case-02","operation":"search","search":{"query":"בדיקה","scopePath":"Y:\\Business","mode":"content","limit":150}},
    {"id":"case-03","operation":"search","search":{"query":"בדיקה","scopePath":"C:\\Business","mode":"everything","limit":150,"offset":1000}},
    {"id":"case-04","operation":"preview","search":{"query":"בדיקה","fileType":"pdf","limit":1}}
  ]
}
```

להחליף את התיקיות והחיפוש מקומית בתרחישים תקינים. המפתח נקרא מקובץ המחבר
במחשב, אינו מופיע בארגומנטים או בדוח. יש להריץ משורש המאגר:

```powershell
node tools/measure-document-bridge.mjs .work/plan.json .work/baseline-computer-1.json
node tools/measure-document-bridge.mjs .work/plan.json .work/after-computer-1.json .work/baseline-computer-1.json
```

למדוד אותה תכנית לפני ואחרי השדרוג; להשתמש ב־computer-2/3 לבסיס עצמאי בכל
מחשב. הכלי מבצע קריאה/תצוגה בלבד ומציג firstRequestMs, P50/P95, שלבים, כשלים
ותשובות חלקיות. חריגה של יותר מ־20% ב־P95 מחזירה קוד יציאה 1 לצורך בדיקה,
ואינה הוכחה לבדה לרגרסיה. דוח ראשון ללא השוואה הוא Baseline בלבד.

להרחיב את המטריצה לשם ותוכן ב־C וב־Y, מאות/אלפי תוצאות, עמוד ראשון/מתקדם,
ריבוי מוסתרים, PDF רגיל/אינטראקטיבי, Word/Excel, פתיחה ראשונה וחוזרת, Y מנותק
ואיטי ושינוי מיפוי מבוקר. להשתמש בתיקייה סינתטית ובחלון בדיקה לשינוי מיפוי;
לא לנתק כונן עם שמירות פעילות. כשלים צפויים בכונן מנותק עדיין מדווחים ככשלים
לבדיקה אנושית. אין לשנות הרשאות כדי להשיג זמן טוב יותר.

הכלי מודד HTTP כולל קריאת התשובה, לא ציור ממשק או Windows Preview Handler.
למדוד בנפרד בדפדפן ב־DevTools את משך הבקשה ועד שהתצוגה מוכנה, ולפתוח Office
בפועל. firstRequestMs אינו מבטיח מטמון קר; למדידת קור אמיתי להתחיל בתהליך
חדש בלי למחוק פרופיל/מטמון עסקי. לשמור גרסאות, תנאי רשת ועומס לצד הדוח המקומי.

## סיכונים ותכנון שנשארו פתוחים

מפתחות נפרדים לכל אתר והרשאות לפי יכולת עדיין אינם ממומשים. הוגדר פרוטוקול
מפורט עם אישור Windows מקומי, תוקף קצר, ביטול עצמאי, מעבר ו־Rollback במסמך
BRIDGE_SCOPED_PAIRING_DESIGN_20261109.md. זהו שחרור נפרד עם בדיקות תאימות.

אסימוני הענן עדיין נגישים ל־JavaScript. המסמך SESSION_ARCHITECTURE_REVIEW_20261109.md
משווה את המצב הקיים, הקשחה ו־BFF/HttpOnly, כולל עלויות, CSRF, אופליין, חידוש,
כמה מחשבים ו־Rollback. לא בוצע שינוי Sessions לפני אישור התכנון והבדיקות.
גם סיכוני אותו משתמש Windows, MFA שטרם הופעל והקשחת מערכת ההפעלה אינם
נפתרים במיזוג קוד. אין כאן הצהרה על אפס חולשות או השלמת בדיקת חדירה.
