# הוראות השלמת ההקשחה בשלושת המחשבים

עדכון: 9 בנובמבר 2026. דוח המצב הטכני נמצא ב־`SECURITY_ROLLOUT_STATUS_20261108.md`.

## 1. לפני העדכון

פתח את שתי המערכות בכל מחשב וודא שהשמירות הסתיימו ושהסנכרון לענן תקין.
אם יש עבודה מקומית שטרם עלתה, שמור גיבוי מוצפן לפני החלפת גרסאות.
אין למחוק את נתוני הדפדפן, קובצי ההצמדה או תיקיות ה־Bridge כחלק מעדכון רגיל.

## 2. עדכון הקוד בכל מחשב

פתח מסוף בתיקיית המאגר באותו מחשב:

```powershell
git status --short
git fetch origin --prune
git switch main
git pull --ff-only origin main
```

אם הפקודה הראשונה מציגה שינויים שלך, שמור אותם לפני החלפת הענף; אין להריץ
`reset --hard` או למחוק אותם. ניקוי ענפים ב־GitHub אינו מעדכן אוטומטית עותקים
מקומיים במחשבים האחרים. אין צורך ליצור ענף חדש לשימוש רגיל במערכת.

## 3. התקנה מחדש של שני המחברים בכל מחשב שמשתמש בהם

הרץ מתוך הקוד המעודכן:

1. `netunim-kupa\bank-bridge\install_bank_bridge.bat` — הגרסה הצפויה היא Bank Bridge **78**.
2. `netunim-orders\document-bridge\install_document_bridge.bat` — הגרסה הצפויה היא Document Bridge **47**.

משיכת Git לבדה אינה מחליפה את עותק התוכנה המותקן ואת פריטי ההפעלה של Windows.
המתקינים משתמשים ב־Node פרטי ומאומת; אין צורך להחליף ידנית את Node הכללי במחשב.
יש להמתין להצלחת בדיקות המתקין. אם הוא מציג כישלון, אין להתעלם ממנו או להפעיל
ידנית עותק ישן במקביל.

ב־Document Bridge בחר רק תיקיות מסמכים עסקיות. אין לבחור כונן שלם, תיקיית
משתמש שלמה או Downloads מעורבת. לשינוי הרשימה המקומית הרץ
`netunim-orders\document-bridge\configure_document_bridge.bat` ופעל לפי הבורר.
ללא תיקיות מורשות חיפוש וקבצים ייחסמו בכוונה.

פתח את שני האתרים ובדוק שהמחברים מחוברים, שחיפוש מסמך עסקי עובד ושסנכרון הבנק
והאשראי מחזיר מידע תקין. אין צורך להפיק מסמך פיננסי חדש לצורך הבדיקה.
מפתחות ההצמדה נשמרים מקומית; אם האתר מבקש הצמדה, השתמש במפתח מהמחשב המתאים
בלבד. אין לשלוח אותו לתמיכה, לצרף אותו לדוח או להעתיק אותו למחשב אחר.

## 4. הפעלת MFA פעם אחת בחשבון, לאחר פריסת שני האתרים

תחילה ודא שבכל שלושת המחשבים נטענה גרסת האתר החדשה, ובמסך ההתחברות מופיע
שדה קוד מאפליקציית אימות. לאחר מכן:

1. פתח [אבטחת החשבון בניהול ההזמנות](https://orders.bargig-furniture.com/security.html)
   או [אבטחת החשבון בקופה](https://kupa.bargig-furniture.com/security.html).
2. התחבר באימייל ובסיסמה הקיימים ובחר **הוסף אפליקציית אימות**.
3. סרוק בטלפון את ה־QR באפליקציית האימות שלך. שמור את אפשרות השחזור שלה או
   עותק מוצפן/לא־מקוון של המפתח במקום נפרד ממחשבי המחברים. אל תשלח QR או מפתח לתמיכה.
4. הזן קוד בן שש ספרות ובחר **אמת והפעל**. הודעת הצלחה היא האישור שהרישום הושלם.
5. התחבר מחדש בכל אתר ובכל מחשב עם הסיסמה וקוד האימות. הפעלת גורם חדש עשויה
   לסיים התחברויות קיימות. הפעל שעון אוטומטי בטלפון אם קודים תקינים נדחים.

זהו אותו חשבון Supabase בשתי המערכות; אין צורך להירשם בנפרד בכל מחשב.
הקוד משתנה — אין לשמור קוד חד־פעמי כתחליף לאפליקציה. לאחר ההפעלה, סיסמה בלבד
לא תספיק גם לקריאה ישירה לטבלאות, ל־RPC ולתמונות שיקים פרטיות.

אבד הטלפון וכל אפשרויות השחזור? בעל פרויקט Supabase צריך לאמת את זהות הבעלים
ולאפס את גורם ה־MFA דרך ניהול Auth. אין מנגנון עוקף באתר ואין קוד שחזור קבוע
שהסוכן יצר. אין להסיר גורמים מאומתים כחלק מתחזוקה רגילה.

## 5. סביבת בדיקות ו־Preview

פרויקט הייצור הוא `bupoidcurcxuypfrjqio`; פרויקט הבדיקות הנפרד הוא
`nckszremdktftbhimgxc` (`netunim-staging`) באותו ארגון. הרשמה ציבורית חסומה.
בנייה חדשה ל־Preview בוחרת Staging, וכתובות Preview של שני פרויקטי Pages מוגנות
גם ב־Cloudflare Access. כדי לצפות בהן יש להיכנס עם חשבון הבעלים המורשה.

אין להעתיק ל־Staging מידע אמיתי, פרטי בנק, אסימוני Google או סודות Morning
של הייצור. לבדיקת ספק אמיתי יש להגדיר OAuth Client נפרד ופרטי Morning Sandbox
נפרדים. עד אז חיבורים אלה בסביבת הבדיקות נשארים לא מוגדרים בכוונה.

## 6. בדיקות Windows וגיבויים בכל אחד משלושת המחשבים

בדוק בהגדרות Windows שהדיסק מוצפן באמצעות BitLocker או הצפנת מכשיר, שחשבון
המשתמש מוגן, שיש נעילת מסך אוטומטית וש־Microsoft Defender מעודכן.
שמור גיבויים מוצפנים, כולל גיבוי לשחזור מפתחות הענן אצל הבעלים.
DPAPI נקשר לחשבון Windows; העתקת קובץ מוצפן למחשב אחר אינה גיבוי נייד שמבטיח שחזור.
אין למחוק פרופיל Windows ישן לפני שמירת גיבוי ניתן לשחזור.

אם בעבר שיתפת דוחות התקנה, אבחון או מפתחות הצמדה, נקה עותקים מיותרים והחלף
את המפתח המקומי וההצמדה לפי נוהל תחזוקה. אבחון חדש מצומצם ופג תוקף אוטומטית;
דוחות ישנים שיוצאו בנפרד אינם נמחקים מעצמם.

## מגבלות שנשארות

נשארנו במסלול Supabase Free לפי החלטת הבעלים. הגנת סיסמאות שדלפו לא הופעלה
משום שהשירות דרש שדרוג בתשלום. MFA יגן על החשבון האמיתי רק לאחר שתשלים את הרישום.
אסימוני התחברות והצמדה של היישומים עדיין נגישים ל־JavaScript במקור שלהם;
מעבר לשרת מתווך עם HttpOnly ופרוטוקול הצמדה קצר־חיים ונפרד לכל אתר נשארים
עבודה ארכיטקטונית נוספת. אין לראות בדוח אישור לאפס חולשות או בדיקת חדירה מלאה.
