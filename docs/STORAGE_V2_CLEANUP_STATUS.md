# Storage V2 cleanup status

The two primary computers use Storage V2. The linked account's server minimum writer protocol is 2 for Orders, Kupa, and Shared Checks. A read-only inventory on 2026-10-01 found one owner with business documents and no owner at protocol 1 in those domains. This does not prove the contents of any browser's local IndexedDB.

Main V2 now writes and replays projection 2 only. Main checkpoints containing `checks` or an older projection fail closed; Shared Checks V2 owns `checks` and `bankEvents`. Historical Shadow checkpoints cannot be promoted to Primary or cloud authority. An unmarked, fenced account can still discard an old local head and atomically adopt verified cloud Main and Shared documents. Fresh local birth creates both V2 journals from current initial state without reading V1.

Orders Main cloud saving now uses only V2 journal flights and writer v6. Its normal save, cloud UI, startup, and transport no longer call the V1 Main outbox writer or v5 Main RPC. The Orders browser adapter no longer implements a V1 Main outbox writer, reads a V1 business snapshot on startup, or lets JSON restore use V1 pending state as its guard. Main recovery explicitly opens V2 and still captures an embedded historical workbook, if present, into the independent workbook store. Shared V2 exposes conservative local-work status, used by the Orders and Kupa bank-snapshot guards so pending checks cannot be missed merely because the retired V1 outbox is empty. A reserved `upload-local` owner-transfer intent remains `upload-local` when the cloud UI is reopened.

Kupa browser recovery now reads only Main V2 and no longer chooses a LocalStorage/IndexedDB V1 business snapshot or merges Main/Shared V1 pending state into the visible model. It preserves the already hydrated Shared Checks state when reopening the local Main checkpoint. An unmarked browser without a V2 checkpoint fails closed; an authenticated fenced browser uses cloud adoption before this recovery path. The independent workbook capture remains in place.

Kupa Main cloud saving now also uses only V2 journal flights and writer v6. The separate V1 Main pending/outbox modules and their ordinary save, poll, conflict, restore and cloud UI branches have been removed. A failed local V2 commit cannot start a cloud write. Independent finance-only updates still apply without replacing the Main cloud head. The Shared Checks V2 journal remains the sole active checks writer.

Cleanup remains incomplete. Orders and Kupa no longer expose Shared Checks V1 base, bank-event, pending-payload, or presence readers: retired outboxes cannot be replayed into or block the active V2 model. Orders also removed its unused Shared V1 storage adapter and Main outbox presence verifier. Kupa checks the active authenticated account owner before applying a cloud document to the visible model; detached V2 owner transfer performs the actual durable adoption. A completed V2 handoff clears an obsolete local-adoption reservation atomically. The idle legacy-retirement scheduler and its IndexedDB deletion API have been removed. Orders retains a narrow IndexedDB helper for the active V2 restore group only; a fresh installation no longer creates the historical `snapshots` store. Historical SQL public wrappers remain. Continue cleanup by following the production call graph and replacing old test fixtures with V2 scenarios. Keep the server protocol fence, V2 journal, local birth, owner transfer, boundary coordinator, bootstrap, and cloud adoption.

Do not edit applied SQL migrations or delete functions by version suffix alone: `list_incomplete_restore_groups_v5` is still a production read endpoint, and some old names may have server-side dependencies. A new SQL migration needs a dependency audit before dropping public legacy RPCs. Old business records on a previously used device may remain physically present, but production startup no longer reads or uploads them. The Settings reset option can clear local site data when needed. Do not delete storage by a `.v1` wildcard: session and preference keys are unrelated to retired business storage.
