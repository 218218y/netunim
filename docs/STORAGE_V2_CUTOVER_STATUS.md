# מצב מעבר Storage V2 — 24 בספטמבר 2026

הקוד כולל כעת מסלול ייצור ל־V2 מקומי בשתי האפליקציות. ב־startup של owner מקומי, לפני הצגת נתונים או פתיחת עריכה, נשמרת תוכנית migration ב־IndexedDB, מאותחלים Main ו־Shared Checks, נבדק שוויון מול המקור, ורק אז נכתב marker מקומי עמיד. לאחר restart באמצע התהליך משתמשים באותה תוכנית קפואה. מקור V1 נקרא לצורך migration בלבד; אין ליצור ממנו outbox חדש. בקופה גם גיליון ישן נשמר כחלק מהתוכנית ונלכד באחסון הגיליונות לפני ה־marker.

העלאה ראשונה מ־`local V2` לחשבון משתמשת ב־owner transfer עמיד וב־runtimes מנותקים שמכוונים לחשבון היעד. בחירת המשתמש בין `upload-local` ל־`load-account` קובעת את הכיוון; מסמך Main קיים אינו נדרס בהעלאה. Main ו־Shared מוכנים, מסתנכרנים ונבדקים מול הענן לפני כתיבת marker לחשבון ולפני החלפת owner. קריסה או lost ACK ממשיכים את קבוצת ה־bootstrap ואת מזהי הפעולות המקוריים. בזמן המעבר העריכה נעולה והמודל של חשבון היעד אינו מוצג לפני activation. מעבר יזום בין שני חשבונות מחוברים עדיין אינו מסלול UI נתמך; הכניסה לחשבון אחר נחסמת לפי owner העמיד. שני המחשבים המיועדים למעבר משתמשים באותו חשבון, ולכן מסלול זה אינו חלק מחלון ה־cutover שלהם.

ה־journal, ה־rebase האטומי, Shared Checks Primary, סנכרון RPC, restore/import, first-cloud של חשבון קיים ו־production cutover coordinator נשארים כפי שאומתו בשלבים הקודמים. `checks` עדיין מופיע בעותקי Main ישנים כמידע לא־סמכותי; Shared Checks הוא הסמכות. V1 עדיין קיים בקוד לצורך migration ו־drain, ולכן אין למחוק אותו בשחרור ה־cutover. בדיקות V1 הוותיקות רצות מול עותק אתר מבודד עם startup תאימות; בדיקת `runtime_local_birth_gate.py` מריצה את קוד ה־production ללא שינוי ומנטרת כתיבות V1 כבר מהניווט הראשון.

**עדיין לא בוצע מעבר בשני המחשבים.** לפני הנחיה לבצע אותו נדרשים: תוצאת CI מלאה של אותו commit, בדיקת zero-V1 בדפדפן לאורך fresh local birth ו־local→account, אימות גיבויים ושערי preflight לחשבון הקיים. אם אחד מהם נכשל, אין להפעיל cutover או למחוק נתוני דפדפן. לאחר מעבר מוצלח בשני המחשבים מבצעים תקופת שימוש קצרה עם V2 ככותב יחיד, ורק אחריה שחרור cleanup נפרד שמסיר את ה־V1 ואת העתק `checks` מ־Main. סדר הפעולות במחשבים נמצא ב־[STORAGE_V2_TWO_COMPUTER_RUNBOOK.md](STORAGE_V2_TWO_COMPUTER_RUNBOOK.md).
