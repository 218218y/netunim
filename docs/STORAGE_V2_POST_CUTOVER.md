# Storage V2 — מצב נוכחי

עודכן ב־25 בספטמבר 2026. שני המחשבים הראשיים של החשבון הפעיל עברו ל־Storage V2, וסימון `storage_writer_protocol=2` פעיל בשרת עבור Orders, קופה וצ׳קים משותפים. האתר משתמש ב־writer v6. ה־server fence דוחה כתיבות ממסלולי v5 ישנים ומכתיבה ישירה למסמכי הליבה. אין צורך לבצע שוב cutover בשני המחשבים.

## מכשיר חדש או מכשיר ישן

התקנה נקייה מתחילה ב־Local V2. לאחר התחברות לחשבון הקיים יש לבחור טעינה מהענן ולהמתין לשחזור Main ו־Shared Checks לפני עריכה.

מכשיר ישן של החשבון שכבר fenced, שאין בו account marker, ננעל עד לאימות מקוון של זהות ופרוטוקול השרת. בטאב הראשי הוא קורא את Main ואת Shared Checks מהענן, מאמת את שניהם ומתקין את שני ה־checkpoints, שני ה־cursors, שיוך ה־owner וה־marker ב־transaction אחת. נתוני V1 מקומיים במכשיר כזה נזנחים לפי החלטת בעל החשבון: הם אינם נקראים, אינם מועתקים ל־quarantine, אינם ממוזגים ואינם נשלחים לענן. `legacyDisposition: discarded` ב־marker הופך outbox V1 שנשאר פיזית ללא־פעיל גם אחרי restart. מכשיר שמכיל journal V2 פעיל או מעבר עמיד שלא הושלם **אינו נדרס** במסלול הזה; יש לבדוק אותו או להשתמש באיפוס המקומי המכוון.

חשבון אחר שעדיין מסומן כ־server protocol 1 אינו חוזר לעבוד ב־V1 בגרסת האתר החדשה. העריכה נחסמת עם `upgrade-required` עד לשדרוג מפורש של אותו חשבון. החשבון הפעיל כבר מסומן 2 ולכן אינו מושפע.

## איפוס מקומי מכוון

בשתי האפליקציות קיימת פעולה בהגדרות לאיפוס נתוני האתר במכשיר זה. היא מאמתת תחילה שאפשר לקרוא את מסמכי Main ו־Shared Checks מהענן, מציגה אישור מפורש על אובדן שינויים מקומיים, ומעבירה את הטאבים לדף איפוס נפרד. דף האיפוס מוחק את אחסון ה־origin, המטמונים ו־Service Worker, מאמת את המחיקה ואז פותח מחדש את האתר. אין להשתמש בפעולה על מחשב שמכיל שינוי מקומי שרוצים לשמור. היא אינה מוחקת נתונים בענן או גיבויים חיצוניים.

## מה עדיין נותר לנקות בקוד

- V1 writers, outboxes ו־readers היסטוריים עדיין קיימים בחלק ממודולי compatibility. כתיבת V1 רגילה חסומה גם בדפדפן ללא marker; רק ניקוז migration מפורש יכול להגיע לכותב ישן. המימושים וה־call-sites הישנים טרם נמחקו פיזית.
- Main V2 מסיר את עותק `checks` דרך migration עמיד לאחר שחזור Shared, ושומר `mainProjectionVersion=2`. פעולות Main חדשות על `checks` נדחות. `legacyCollections` עדיין מאפשר קריאת checkpoints ישנים בזמן השדרוג, ולכן קוד התאימות טרם נמחק פיזית.
- מיגרציית `20260925120000_storage_writer_internalization.sql` נפרסה: פונקציות v6 קוראות למימושים קנוניים ב־`netunim_internal`, כולל שחזור, בנק ואשראי. פונקציות v5 הציבוריות נשארות זמנית כ־wrappers. המיגרציה הבאה שוללת מהדפדפן EXECUTE על writers ישנים וכתיבה ישירה למסמכי הליבה; `DROP` ייעשה רק לאחר בדיקת תלויות נוספת. ה־server fence נשאר גם בארכיטקטורה הסופית.
- לאחר שחזור Main ו־Shared V2 בטאב הראשי, אימות marker עמיד ובחשבון גם אימות protocol 2 בשלושת התחומים, ניקוי רקע מוחק מפתחות business V1 ידועים וארבע רשומות IndexedDB ישנות לכל היותר. מחיקת IndexedDB קודמת למחיקת LocalStorage; כשל גורם לניסיון חוזר בהפעלה הבאה. marker קטן מונע בדיקות חוזרות אחרי הצלחה. Session, העדפות, גיבויים, handles ונתוני V2 נשארים. אין מחיקת wildcard של `.v1`.

## סנכרון בנק ואשראי

מיגרציית `20260924180000_finance_storage_writer_protocol_v2.sql` מוסיפה כניסות v6 לסנכרון הפיננסי; האתר דורש `financeFencing=2`. מחבר האשראי הנוכחי הוא v60. הודעת השהיה בעקבות 403/429 היא cooldown של המחבר; אין להסיק ממנה כשלעצמה ש־Storage V2 נכשל. במקרה של כשל רענון חדש יש לבדוק את הודעת האתר ואת קוד תגובת Network בלי לשלוח סיסמה או token.
