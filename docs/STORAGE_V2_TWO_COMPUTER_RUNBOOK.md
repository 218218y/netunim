# מעבר Storage V2 בשני מחשבים

**מצב נוכחי: עדיין לא לבצע את המעבר בפועל.** מסלול ההקמה המקומית V2 ומסלול העלאה ראשונה `local → account` אינם מחוברים יחד בייצור. המסמך הזה הוא סדר הפעולות לביצוע רק אחרי ששער השחרור יאושר במפורש.

## שער לפני תחילת המעבר

- אותה גרסת Orders וקופה מותקנת בשני המחשבים, וכל 40 חבילות הבדיקה ושער zero-V1 עברו לגרסה המדויקת הזאת.
- התקנה חדשה עוברת `fresh → local V2 → account V2` בלי כתיבת business V1; import ושחזור מקומיים עוברים restart אחרי כל שלב.
- בחשבון הקיים אין pending V1 או flight/control/boundary תקועים; Main ו־Shared Checks משוחזרים ומתאימים לענן.
- יש עותקי גיבוי מאומתים של Orders ושל הקופה, הכוללים גם צ׳קים ואירועי בנק, וכן אפשרות לשחזר את מסמכי הענן אם יידרש.

## חלון המעבר

1. מסנכרנים את המצב הקיים ויוצרים גיבויים. סוגרים את כל הטאבים של Orders ושל הקופה בשני המחשבים, כולל טאבים שהושארו ברקע. לא עובדים בגרסה ישנה במהלך החלון.
2. מעדכנים את שתי האפליקציות **בשני** המחשבים לאותה גרסה. בודקים ש־Service Worker אינו מגיש קבצים מגרסה קודמת.
3. פותחים במחשב A את Orders ואת הקופה, מאמתים שזה אותו חשבון, ומפעילים את פעולת המעבר ל־Storage V2 מתוך ההגדרות של כל אפליקציה. ממתינים בכל אחת לסיום ולמצב מסונכרן, בלי pending או שגיאת transition.
4. רק אחרי ששתי האפליקציות במחשב A סיימו, פותחים במחשב B את Orders ואת הקופה. מאמתים שזה אותו חשבון ושכל נתוני Main, הצ׳קים ואירועי הבנק תואמים לפני עריכה.
5. בודקים שינוי קטן מ־A ל־B ושינוי קטן מ־B ל־A, עריכת צ׳ק, הפקדה/החזרה, עבודה אופליין ולאחריה restart וסנכרון. בודקים גם import/restore בסביבת ניסיון או אחרי גיבוי מתאים.
6. משאירים V1 בקוד כ־reader/drain בלבד לתקופת שימוש קצרה. מנטרים שאין כתיבות V1, pending ישן, owner mismatch או פעולות V2 תקועות. מסירים את V1 רק בגרסת cleanup נפרדת אחרי שהשימוש האמיתי עבר תקין בשני המחשבים.

אם אחד השלבים מציג חוסר התאמה, לא ממשיכים למחשב השני ולא מוחקים נתוני דפדפן, marker או outbox. שומרים את הגיבויים ואת מצב ה־IndexedDB ומבררים את הסיבה לפני פעולה נוספת.
