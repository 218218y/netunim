# מעבר Storage V2 בשני המחשבים

**סטטוס: מעבר שני המחשבים הראשיים כבר בוצע, לפי דיווח המשתמש.** השלבים להלן נשמרים כתיעוד היסטורי ואין לבצע אותם שוב. המשך העבודה והנחיות למכשירים ישנים נמצאים ב־[STORAGE_V2_POST_CUTOVER.md](STORAGE_V2_POST_CUTOVER.md). שני המחשבים משתמשים באותו חשבון Supabase.

1. ודאו ש־Orders והקופה מסונכרנים, וצרו גיבוי JSON מאומת לשתי האפליקציות הכולל צ׳קים ואירועי בנק. שמרו את הגיבויים מחוץ לדפדפן.
2. סגרו את **כל** הטאבים של Orders ושל הקופה בשני המחשבים. אל תשאירו טאב ישן או Service Worker המגיש קבצים מגרסה מעורבת.
3. התקינו את אותה build מאומתת של שתי האפליקציות בשני המחשבים ובדקו שמספר הגרסה וקובצי ה־Service Worker עדכניים.
4. פתחו במחשב A את Orders בלבד. בהגדרות לחצו **״השלם מעבר Storage V2״** והמתינו ל־**״Storage V2 פעיל״**, ללא pending או שגיאת transition. סגרו את הטאב, פתחו את הקופה באותו מחשב ובצעו בה את אותו מעבר. אל תערכו נתונים בזמן ששתי האפליקציות עוברות.
5. רק לאחר ששתי האפליקציות במחשב A נקיות, פתחו במחשב B את Orders, בצעו בה את מעבר Storage V2 ואמתו שהנתונים והצ׳קים תואמים לענן. סגרו אותה, פתחו את הקופה ובצעו בה את המעבר. לפני עריכה בדקו שגם אירועי הבנק והיתרות תואמים. אין להמשיך אם אחד מארבעת ה־markers חסר או אם מוצגת שגיאת סנכרון.
6. בצעו שינוי קטן מ־A ל־B ושינוי קטן מ־B ל־A. בדקו עריכה, הפקדה, החזרה ומחיקה של צ׳ק; אחר כך שינוי אופליין, סגירת דפדפן, פתיחה מחדש וסנכרון. בצעו import/restore רק לאחר גיבוי מתאים ובסביבת ניסוי או על נתון שתוכנן לכך.
7. השתמשו בגרסת ה־cutover זמן קצר עם V2 ככותב יחיד. בדקו שאין V1 business writes, pending ישן, owner mismatch, flight/control/boundary תקועים או שחזור דרך V1.

אם preflight, parity או סנכרון נכשלים, עוצרים לפני מחשב B. לא מוחקים IndexedDB, LocalStorage, marker או outbox כדי ״לנסות שוב״. שומרים את הגיבויים ומבררים את הסיבה. הסרת V1 והעתק `checks` מ־Main תבוצע בשחרור cleanup נפרד רק לאחר ששני המחשבים עברו תקופת שימוש תקינה.
