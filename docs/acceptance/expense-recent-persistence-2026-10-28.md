# Recent-list retention and real history-filter dispatch

Verified causes: the lazy Finance action list omitted `morning-expense-history-filter`, although the expense feature declared it. Direct component tests could dispatch it; the actual application's registry could not. The real composition regression reproduces the reported unknown-action error before the fix and exercises both selectors after it.

Full-account refresh results previously lived only in memory. Initial site loading replaced them on reopening, and canonical write results rebuilt the list using only site rows. The controller now restores a bounded IndexedDB display snapshot per owner/environment before considering a site-ledger bootstrap. A completed stable full refresh replaces that snapshot; newly verified site intakes merge by ID, preserve external Morning rows, and persist immediately. The last full refresh date stays visible, without expiry or deletion. Changes made directly in Morning require explicit refresh.

The native read/modify/write transaction preserves site intakes committed by another tab after a scan started and rejects an older completed scan over a newer full snapshot. Cancelled/failed/incomplete scans cannot replace a saved snapshot. Storage failures show an explicit notice; financial creation is not retried. Only ten display rows and bounded recent-write evidence are retained, without URLs, source files, provider payloads or financial journal changes. This cache is local to the browser, not synchronization between devices; clearing browser site data clears it.

History selectors sit compactly beside the section title and wrap on narrow screens. The offered years start at 2026 and grow with the current year, retaining 2026 and later previous years. Unfiltered newest-first browsing still supports the older history.

Validation includes deterministic cache/snapshot tests, real IndexedDB commits and tab-connection races, actual page reload, scoped account/environment reads, cancelled and failed refreshes, real lazy action dispatch, and table/control geometry from 320 to 1920 px. Full CI remains required before merge. No new migration or Edge Function deployment is required for these fixes; deploy complete Orders frontend assets from the verified commit. The earlier optional site-history bootstrap still needs the previously supplied Edge Function when no local snapshot exists.
