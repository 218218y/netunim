# קליטת הוצאות ב־Morning

קליטת הוצאות פועלת דרך [morning-expenses](../../netunim-orders/supabase/functions/morning-expenses) ויומן פעולות נפרד מהפקת הכנסות. התקינו את שרשרת המיגרציות ופרסו את הפונקציה דרך [מדריך Supabase](../operations/supabase.md). הפונקציה דורשת MFA והרשאה שרתית מתאימה. הרשאת דוחות או הכנסות אינה מעניקה גישה להוצאות.

## הגדרה וקבלה

| מטרה | הגדרה |
| --- | --- |
| קריאה | `app_metadata.morning_expenses_read` או `MORNING_EXPENSE_READ_USER_IDS` |
| סביבה ומפתחות עצמאיים | `MORNING_EXPENSE_ENV`,‏ `MORNING_EXPENSE_CLIENT_ID`,‏ `MORNING_EXPENSE_CLIENT_SECRET` |
| כתיבה | הרשאת קריאה וגם `app_metadata.morning_expenses_write` או `MORNING_EXPENSE_WRITE_USER_IDS` |
| כתיבה ב־Sandbox | `MORNING_EXPENSE_SANDBOX_WRITES=true` ותצורת ספקי P תקינה |
| OCR ב־Sandbox | מפתחות Sandbox ייעודיים ו־`MORNING_EXPENSE_SANDBOX_OCR=true` |
| פתיחת כתיבה בייצור | זוג מפתחות עצמאי, `MORNING_EXPENSE_PRODUCTION_USER_ID`,‏ `MORNING_EXPENSE_PRODUCTION_WRITES=true` ותצורת ספקי P תקינה |
| צירוף מקורות בייצור | כתיבה פעילה וגם `MORNING_EXPENSE_PRODUCTION_UPLOADS=true` |
| סיווג P | זהויות מפורשות ב־`MORNING_EXPENSE_P_SUPPLIERS` בפורמט JSON של רשומות עם `id` ו־`taxId`. הפעלת שמירת P היא החלטה נפרדת דרך `MORNING_EXPENSE_PCN_P_WRITES`, לאחר קבלת יצוא PCN874. |

מקור האמת למתגים ולתנאים הוא [configuration.js](../../netunim-orders/supabase/functions/morning-expenses/configuration.js). מתחילים בקריאה ב־Sandbox. בודקים סכום, מע״מ, מספר, ספק וסיווג מול המסמך המקורי באמצעות קריאה חוזרת. לאחר קבלת הקריאה בייצור, בודקים כתיבה מורשית רק עבור הוצאה עסקית אמיתית שיש לקלוט. לפני פתיחת צירוף, בודקים העלאה, קישור, התאוששות ופירוט בדוח. טיוטת OCR אינה הוצאה מאושרת.

## שימוש והתאוששות

- המסך שומר את תקופת הדיווח האחרונה לפי חשבון וסביבה. תאריך החשבונית נפרד מחודש הדיווח. יש לבחור תקופה מתאימה לפני שמירה כשהחשבונית חדשה ממנה.
- בוחרים ספק מזוהה ובודקים את נטו, מע״מ, סה״כ ומספר ההקצאה. קריאת הצעות או זיהוי מקומי של PDF מספקים הצעות. השרת מאמת שדות וסכומים לפני שליחה.
- פירוט תקופתי וסריקת ההוצאות האחרונות משתמשים בקריאות נפרדות. תוצאות חלקיות אינן סיכום מלא. מעבר חשבון או סביבה מבטל פרסום של תוצאות ישנות.
- יומן הפעולות משמר את זהות הניסיון. אם יצירה או העלאה נשארה לא מאומתת, בודקים את אותה פעולה ומשלימים התאמה לפני ניסיון חדש. תשובת קבלה להעלאת קובץ עדיין מחייבת אימות שהקובץ מקושר להוצאה הנכונה.
- לעצירת כתיבות חדשות מכבים את מתג הכתיבה ומשאירים את חשבון וסביבת Morning הנכונים להתאוששות. מתג קבצים נפרד יכול לעצור צירוף חדש. הרשאת העלאה שכבר נמסרה פגה לפי תוקפה. כשיש פעולות פתוחות, שומרים את היומן ואת התאימות בין האתר לפונקציה.

בדקו את הקבלה באמצעות מקרי Morning ב־[תוכנית הבדיקות](../../tests/verification_plan.py) והפרידו בין תוצאה מבודדת לבין קבלת שירות חי.
