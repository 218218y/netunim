# הפקת הכנסות ודוחות ב־Morning

זהו מסלול של Edge Function אחת בלבד בשם [morning-documents](../../netunim-orders/supabase/functions/morning-documents). קובצי הייבוא של הפונקציה אינם שלוש פונקציות נוספות. [קליטת הוצאות](morning-expenses.md) משתמשת בפונקציה ויומן נפרדים.

## התקנה ובדיקה

1. אמתו את שרשרת המיגרציות של היעד. בסביבת בדיקה הגדירו `MORNING_CLIENT_ID`,‏ `MORNING_CLIENT_SECRET` ואת `MORNING_ENV=sandbox` ב־Edge Secrets. שמרו את מפתחות הייצור בנפרד.
2. פרסו את התיקייה המלאה לפי [הוראות פריסת Edge](../operations/supabase.md), באמצעות `supabase functions deploy morning-documents` עם הדגלים והיעד שמפורטים שם.
3. התחברו עם MFA. הפקה דורשת `app_metadata.morning_documents_write=true` או `MORNING_DOCUMENT_WRITE_USER_IDS`. קריאת מסמכים רחבה דורשת `app_metadata.morning_documents=true` או `MORNING_DOCUMENT_USER_IDS`. דוחות דורשים `app_metadata.morning_reports=true` או `MORNING_REPORT_USER_IDS`, וכוללים את הרשאת קריאת המסמכים. מפיק ללא גישה רחבה יכול לקרוא מסמכים שאומתו ביומן שלו באותה סביבה.
4. פתחו חוב בדיקה, ודאו שמופיע Sandbox, הציגו PDF בתצוגה מקדימה, והפיקו מסמך רשמי רק בחשבון Sandbox. השוו סוג, לקוח, סכום, תאריך ומספר מול Morning. בדקו גם חיפוש, צפייה ופירוט דוח. רק לאחר קבלה בסביבת בדיקה יש להגדיר את זוג מפתחות הייצור ו־`MORNING_ENV=production` ביעד המתאים.

## מקור ההכנסה ואימות

- אפשר להפיק מתנועת זכות עסקית סופית ב־ILS עם מזהה ארכיון יציב. העברה נבדקת מול האסמכתא והסכום. בהפקדת צ׳קים אפשר לבחור רק פריטים שהבנק מסר. קישור לחוב הוא בחירה מפורשת ונפרדת מהפקת המסמך.
- קישור הבנק נכתב אחרי קריאה חוזרת ואימות המסמך. בהפקדה מרובת צ׳קים קישור מסמך אחד אינו מסמן את ההפקדה כטופלה אוטומטית. אם הקישור המקומי נכשל לאחר האימות, משלימים אותו במסלול ההתאמה.
- Morning מטפלת בהקצאה לפי הרשאת העסק. האפליקציה קוראת את `allocationNumber` מהמסמך הרשמי. אם המספר חסר, בדקו את ההרשאה ואת פרטי הלקוח ב־Morning והפעילו **בדוק שוב**. אין להוסיף לקוד API Key נוסף של רשות המסים. ביישום, הרף החל מ־1 ביוני 2026 הוא מעל 5,000 ₪ לפני מע״מ לפי [כללי ההקצאה בקוד](../../netunim-orders/site/assets/js/core/invoice-allocation.js). שינוי הרף דורש בדיקת מקור רשמי ועדכון הקוד.

### PCN / ריכוז הכנסות - L

ה־payload של מסמכי ההכנסה אינו שולח כרגע `accountingClassification`. הגדרת העסק ב־Morning קובעת את הסיווג. בדקו בחשבון Sandbox מסמכי 320 ו־400 לפני שינוי ההגדרה או הסתמכות עליה בייצור.

## תוצאה לא ודאית

בקשת הפקה מקבלת מזהה פעולה. רק מעבר אטומי מ־`reserved` ל־`pending` מתיר שליחה. `needs_reconciliation`,‏ `created_unverified` או `local_link_pending` מחייבים בדיקה או המשך של אותה פעולה. אין לשלוח שוב מסמך שכבר התקבל או שגורלו אינו ידוע. `created` מחייב קריאה חוזרת של המסמך והתאמתו לבקשה. היומן שומר מזהים וראיות מינימליות. המסמך הרשמי נשאר ב־Morning.
