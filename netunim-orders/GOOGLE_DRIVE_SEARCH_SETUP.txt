ניהול הזמנות — חיפוש ותצוגה מקדימה ישירה דרך Google Drive
============================================================

מטרת השינוי
-----------
ב-Windows האתר ממשיך להעדיף את המסלול המקומי הקיים: Document Bridge ב-127.0.0.1:8766 + Everything + מנגנוני ה-Preview המקומיים.
ב-Android אין Bridge מקומי ולכן Google Drive הוא מקור המסמכים הראשי.
ב-Windows נוסף failover: אם Document Bridge/Everything אינם זמינים, אינם משויכים, אינם רצים או אינם תואמים לגרסה, האתר עובר אוטומטית ל-Google Drive ומציג הודעה קטנה שמסבירה שהחיבור נעשה דרך Drive כי הגישה המקומית אינה זמינה.

מה עובד דרך Drive
-----------------
- חיפוש שמות: name contains של Google Drive.
- חיפוש תוכן: fullText contains של Google Drive.
- קבצים אחרונים לפי modifiedTime.
- תצוגה מקדימה ישירות בתוך האתר, בלי לפתוח Google Drive, עבור סוגים נתמכים:
  * PDF דרך PDF.js המקומי של האתר.
  * תמונות נתמכות.
  * DOCX/DOCM/DOTX/DOTM דרך docx-preview המקומי.
  * XLS/XLSX/XLSM/XLSB/XLT/XLT(X/M) דרך מציג הגיליונות המקומי.
  * קבצי טקסט/JSON/XML וסיומות טקסט מוכרות.
  * Google Docs / Google Slides / Google Drawings מיוצאים ל-PDF לצורך Preview.
  * Google Sheets מיוצא ל-XLSX לצורך Preview.
- אם הסוג אינו נתמך, אם הבעלים חסם הורדה/ייצוא, אם הקובץ גדול מדי, או אם Google אינה יכולה לייצא אותו — האתר מציג הסבר וכפתור פתיחה רשמי ב-Google Drive.
- לחיצה כפולה/Enter עדיין פותחות את webViewLink הרשמי של Google.

למה נדרש שינוי הרשאה
--------------------
הגרסה הקודמת ביקשה:
https://www.googleapis.com/auth/drive.metadata.readonly

Scope זה מאפשר חיפוש/מטא-דאטה אך אינו מאפשר להוריד את תוכן הקובץ, ולכן לא ניתן לבנות Preview אמיתי בתוך האתר.
הגרסה הזו מבקשת במקום זאת:
https://www.googleapis.com/auth/drive.readonly

האתר משתמש בהרשאה לקריאה בלבד:
- קבצים רגילים יורדים ישירות מה-Drive API באמצעות files.get + alt=media.
- מסמכי Google Workspace מיוצאים דרך files.export לפורמט שהמציג המקומי יודע לקרוא.
- Refresh Token נשמר רק בצד Supabase.
- Access Token קצר-חיים מוחזק בזיכרון הדפדפן בלבד.
- תוכן הקבצים עובר ישירות מ-Google לדפדפן; Edge Function אינה מעבירה את תוכן המסמך.

חשוב: drive.readonly מסווג על-ידי Google כ-Restricted Scope. באפליקציית External/Production יש לוודא שה-OAuth consent/verification של הפרויקט מאושר בהתאם לדרישות Google.

שדרוג חיבור קיים
----------------
אם Google Drive כבר חובר בגרסה הקודמת, ה-Refresh Token הקיים כולל רק metadata.readonly ואינו יכול לקבל אוטומטית הרשאת תוכן חדשה.
לא מוחקים ידנית את הטבלה ולא משנים SQL.
לאחר פריסת ה-Edge Function החדשה האתר יזהה את ה-scope הישן ויבקש חיבור מחדש.
לחץ "חבר Google Drive" ואשר מחדש את ההרשאה. החיבור החדש יחליף בצורה מבוקרת את ה-Refresh Token הישן.

הכנה ב-Google Cloud
-------------------
1. ודא ש-Google Drive API פעיל באותו Google Cloud Project.
2. ב-Google Auth Platform > Data Access הוסף/אשר:
   https://www.googleapis.com/auth/drive.readonly
3. אפשר להשאיר metadata.readonly ברשימת ה-scopes המוגדרים בפרויקט, אבל הקוד עצמו מבקש drive.readonly בלבד.
4. ב-OAuth Web Client ודא ש-Authorized redirect URI כולל בדיוק:
   https://bupoidcurcxuypfrjqio.supabase.co/functions/v1/google-drive-oauth/callback
5. שמור.

הכנה ב-Supabase
---------------
אין migration SQL חדש לשינוי ה-Preview. הטבלה הקיימת google_drive_connections כבר מכילה את עמודת scope הדרושה לזיהוי חיבור ישן.

כן צריך לפרוס מחדש את Edge Function:
  netunim-orders/supabase/functions/google-drive-oauth/index.ts

שם הפונקציה:
  google-drive-oauth

אם Google Drive משתמש באותו OAuth Client של Calendar, אפשר להמשיך להשתמש ב-GOOGLE_CALENDAR_CLIENT_SECRET.
לחלופין אפשר להגדיר GOOGLE_DRIVE_CLIENT_SECRET ייעודי.

סדר פריסה מומלץ
---------------
1. הרץ את verification של הפרויקט.
2. ב-Google Cloud ודא ש-drive.readonly נוסף ל-Data Access.
3. פרוס מחדש את Edge Function google-drive-oauth, כדי שכל חיבור/חיבור-מחדש חדש יקבל מיד את ה-scope הנכון.
4. פרוס את האתר המעודכן מיד לאחר מכן.
5. אין צורך ב-db push נוסף רק בגלל השינוי הזה, אם migration 20260927121000_google_drive_oauth_search.sql כבר נפרס.
6. פתח את האתר, התחבר לענן, ופתח את החיפוש הכללי.
7. אם מופיעה בקשת חיבור מחדש ל-Drive — אשר אותה פעם אחת.

התנהגות Windows / Failover
--------------------------
ב-Windows המקור המועדף נשאר Everything.
המעבר ל-Drive מתבצע רק כאשר הגישה המקומית אינה שימושית, למשל:
- Document Bridge אינו משויך לדפדפן.
- Document Bridge אינו נגיש.
- מפתח Bridge אינו תקין.
- Everything אינו מותקן/אינו רץ/אינו נגיש ל-Bridge.
- Bridge דורש שדרוג לגרסה התואמת לקוד האתר.

במצב fallback:
- תופיע הודעה קטנה: "מחובר דרך Google Drive כי הגישה המקומית אינה זמינה."
- התוצאות מסומנות פנימית לפי המקור כדי ש-Preview/פתיחה תמיד יישלחו לספק הנכון.
- במסך חיבור Drive ב-Windows נשארת גם אפשרות להזין מחדש מפתח Document Bridge ולחזור למסלול המקומי.
- אם החיבור המקומי חוזר לעבוד, הוא חוזר להיות המקור המועדף בפעולה הבאה שמצליחה דרכו.

מגבלות Preview
---------------
- קבצים רגילים מעל 64MB אינם נטענים ל-Preview כדי לא להעמיס על זיכרון הדפדפן; עדיין אפשר לפתוח אותם ב-Drive.
- קבצי טקסט ל-Preview מוגבלים ל-4MB.
- Google מגבילה files.export של מסמכי Google Workspace ל-10MB. אם הייצוא גדול יותר, Google תחזיר שגיאה והמשתמש יוכל לפתוח את המסמך ב-Drive.
- קבצים שהבעלים/מנהל חסם עבורם download/export לא יוצגו בתוך האתר.
- סוגי קבצים שאין עבורם מציג בטוח ומקומי נשארים עם כפתור "פתח ב-Google Drive".
- Google Drive אינו Everything: fullText מבוסס על האינדקס של Google ולכן תוצאות חיפוש תוכן אינן בהכרח זהות לחיפוש המקומי.

בדיקה לאחר פריסה
----------------
Android:
1. חפש PDF ובחר תוצאה — ה-PDF צריך להופיע בתוך אזור ה-Preview באתר.
2. בחיפוש תוכן PDF בדוק שהחיצים עוברים בין ההתאמות דרך PDF.js.
3. חפש DOCX — המסמך צריך להופיע בתוך האתר.
4. חפש XLSX — הגיליון צריך להופיע בתוך האתר.
5. חפש Google Doc — הוא צריך להופיע כ-PDF מיוצא בתוך האתר.
6. חפש Google Sheet — הוא צריך להופיע כ-XLSX בתוך מציג הגיליונות.
7. בדוק קובץ לא נתמך — צריך להופיע הסבר + כפתור פתיחה ב-Drive.

Windows עם Bridge תקין:
1. ודא שהכותרת/מקור נשארים Everything.
2. ודא ש-Windows Preview וכל המציגים המקומיים ממשיכים לעבוד ללא שינוי.

Windows ללא Bridge/Everything:
1. עצור את Bridge או בדוק במחשב ללא Bridge.
2. החיפוש צריך לעבור ל-Google Drive ולא להיתקע.
3. צריכה להופיע הודעת fallback קטנה.
4. Preview דרך Drive צריך לעבוד כמו באנדרואיד.
5. אם מזינים מפתח Bridge תקין מחדש, המסלול המקומי צריך לחזור להיות המועדף.
