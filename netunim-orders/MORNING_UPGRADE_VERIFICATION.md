## שלב ב׳

- ה־instrumenter מזהה החזרי API לפי המבנה: factory רגיל, arrow factory, משתנה תוצאה, destructuring, aliases, החזרים מותנים ו־composition מקונן. אין רשימת שמות דומיין ואין תלות בקידומת `create`.
- רק עותקי הבדיקה הזמניים מקבלים instrumentation. ה־API המקורי אינו מקבל שדות עזר; לא נוספים globals לקוד המפורסם. פונקציות פנימיות שאינן ב־API אינן נחשפות.
- ה־probe שומר על `this`, תומך בהחלפת מתודה ציבורית לבדיקה, ומונע התנגשות של שמות פעולה עם API של הדפדפן. בדיקות האבטחה והסנכרון פונות במפורש ל־`uiModal` ול־`uiStatus` כאשר יש התנגשות שם.
- שכבת ה־bindings השטוחה של הלקוחות הוסרה מ־`main.js`. ניווט ופעולות פונים ל־`domainsCustomers`, והמימוש נשאר במודולי הדומיין.
- contract חדש: `tests/module_probe.test.mjs`, משולב ב־`module_contracts.py` ובאימות המלא.
- לאחר הניקוי, **`verify.bat --no-pause` עבר במלואו**, כולל כל בדיקות runtime, module graph, מודלים עסקיים, Morning, בנק, נכסים, service worker, אישורים וסנכרון (`.work/morning-final-verify.log`).
- בנוסף עברו כל שמונת תרחישי `runtime_sync_postgres.py` מול PostgreSQL מבודד ו־HTTP אמיתי: אובדן תשובה לאחר שמירה, התנגשות ומיזוג נפרד, בשתי האפליקציות ולמסמכים/צ׳קים.
- `supabase_candidate.py` עבר: התקנה נקייה של כל שרשרת ה־migrations תואמת לסכמה שנבדקה, למעט גיבוי ה־Morning שקיים רק בשדרוג התקנה קודמת. גם בדיקות ההרשאות והנעילות עברו. `sync-assets --check` ו־release gate עברו.

## העלאת האתר

לפי בקשת המשתמש, הקבצים מוכנים להעלאה עצמאית; לא בוצעה העלאה מחודשת ל־Cloudflare. שינוי מסד הנתונים ו־Edge גרסה 3 כבר הוחלו במהלך שלב א׳. גיבוי ה־ledger נשמר. אין להריץ שוב את ה־migration שכבר הוחלה.
