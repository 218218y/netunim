ניהול הזמנות — הוראות הפעלה ופיתוח
===================================

קובץ ההפעלה
------------
- מקור האפליקציה הפעיל הוא netunim-orders/site/index.html.
- לפריסה מעלים רק את תיקיית site/.

עבודה באתר / PWA
----------------
1. פתח את האתר שהועלה.
2. התחבר ל-Supabase.
3. נתוני ניהול ההזמנות נשמרים ב-order_management_documents; הצ׳קים נשמרים ב-shared_checks_documents.
4. שינוי מקומי נשמר גם בדפדפן עד לסנכרון.

פיתוח מקומי
-----------
- משתמשים באותו site/index.html, אין גרסת HTML מקומית נפרדת.
- מומלץ להגיש את תיקיית site דרך http://localhost (VS Code Live Server, שרת סטטי של סביבת הפיתוח וכדומה).
- פתיחה ישירה ב-file:// אינה נתמכת: מודולי ESM ו-Service Worker דורשים HTTP(S)/localhost.
- משורש המאגר: python -m http.server 8082 --directory netunim-orders/site
- לאחר מכן פתח http://localhost:8082. אין להגיש את שורש המאגר, המכיל קבצים שאינם מיועדים לפרסום.

תיקייה מקומית וגיבויים
----------------------
- מתוך הגדרות וגיבוי אפשר לחבר תיקייה מקומית גם כאשר עובדים מהאתר או מ-localhost.
- קובץ העבודה נכתב ל-data/orders-data.json.
- גיבויים נכתבים ל-backups/.
- שמות קובצי הנתונים/גיבויים/ייצוא נוצרים באנגלית בלבד (למשל orders-data.json, orders-backup_..., orders-export_...).
- handle של התיקייה נשמר ב-IndexedDB. אם Chrome/Edge דורש הרשאה מחדש, התיקייה נשארת זכורה ומופיע כפתור לאישור מחדש.
- אם אין כרגע הרשאה לתיקייה, השמירה בדפדפן ובענן ממשיכה; התיקייה היא שכבת גיבוי נוספת.

Supabase
--------
- netunim-orders/supabase/setup.sql — דומיין ניהול הזמנות.
- netunim-kupa/supabase/setup.sql — דומיין הקופה.
- netunim-orders/supabase/shared/setup.sql — דומיין הצ׳קים המשותף.
- cutover/preflight/postflight שבתיקיית shared הם כלי מעבר/בדיקה ולא מסלול עבודה יומיומי.

זהירות
------
- אל תנקה Site Data כאשר יש שינוי Offline שעדיין לא הסתנכרן.
- אל תעלה data/, backups/, SQL או קבצי הוראות לאתר הציבורי.
- אין לשים service_role/secret בקוד הדפדפן.
